摘要

随着互联网技术的快速发展，信息安全问题日益凸显，基于大整数分解困难性的 RSA 等公钥密码体制被广泛应用于电子商务、在线支付和隐私通信等关键场景。大整数分解作为评估 RSA 安全性的重要手段，一方面推动了数论与算法理论的发展，另一方面也为密码系统安全评估提供了实践工具。现有大整数分解工具多部署在桌面端或服务器端，对使用环境和专业背景有较高要求，缺乏“随时可用、轻量便捷”的移动端解决方案。微信小程序具有“无需安装、即开即用、跨平台运行”等优势，为在移动终端上实现大整数分解提供了一条新路径。

本文以“基于微信小程序的大整数分解系统设计与实现”为研究课题，围绕 Pollard’s Rho 随机化分解算法和 Miller‑Rabin 素性检测算法，结合 JavaScript BigInt 高精度整数类型与微信小程序双线程架构，设计并实现了一套支持大整数分解的微信小程序系统。系统从“前端交互–算法核心–数据存储–云端协同”四个层面进行整体设计，前端实现了整数输入校验、位数统计、分解模式切换、动态进度展示与结果可视化；算法核心对 Pollard’s Rho 算法进行轻量化优化，引入 Brent 判环思想、分级迭代上限和部分分解策略，在有限算力的移动终端环境中提升分解效率与稳定性；数据层通过本地存储管理分解历史与用户信息，预留云端分解接口，为大规模整数的协同计算奠定基础。

在实现过程中，本文重点解决了移动终端算力有限导致的分解效率受限、超大整数导致的计算时间不可控、小程序前端交互与后台计算协同困难等问题。通过在支持环境下使用 Worker 线程承载密集计算、在不支持 Worker 的环境中采用主线程异步分块计算策略，有效避免了界面卡顿与“假死”现象。系统根据用户等级（普通用户、VIP 用户、SVIP 用户、管理员）动态调整可分解整数位数，并结合时间阈值与位数阈值对超出本地能力范围的任务进行友好提示和部分分解结果返回。

测试结果表明：在常见移动设备上，系统可以在 30 秒内稳定完成 100 位以内大整数的分解，成功率达到 95% 以上，界面响应时间一般不超过 500 ms，历史记录和用户管理等辅助功能运行稳定。研究工作表明，将大整数分解算法移植到微信小程序平台是可行且具有应用价值的，为密码学教学、算法验证和轻量化安全工具的实现提供了一种新思路。

**关键词**：大整数分解；Pollard’s Rho 算法；Miller‑Rabin 素性检测；微信小程序；BigInt

Abstract

With the rapid development of the Internet, information security has become increasingly critical. Public‑key cryptosystems such as RSA, whose security is based on the hardness of integer factorization, are widely used in e‑commerce, online payment and secure communication. Integer factorization not only plays a key role in evaluating the security of RSA, but also promotes the development of number theory and algorithm design. However, most existing factorization tools run on desktops or servers, which lack portability and are not friendly enough for lightweight and real‑time usage on mobile devices. WeChat Mini Programs, featuring “no installation, instant use and cross‑platform compatibility”, provide a new way to implement an integer factorization tool on mobile platforms.

This thesis focuses on the design and implementation of a WeChat Mini Program based large integer factorization system. Based on the Pollard’s Rho algorithm and the Miller‑Rabin primality test, together with JavaScript BigInt and the dual‑thread architecture of WeChat Mini Programs, we design an integrated system consisting of frontend interaction, algorithm core, data storage and cloud collaboration. The frontend supports integer input validation, digit counting, mode switching, dynamic process display and result visualization; the algorithm core optimizes Pollard’s Rho for constrained environments by introducing Brent‑style cycle detection, adaptive iteration limits and partial factorization strategies; the data layer manages local history and user information and reserves interfaces for cloud‑based factorization.

Experiments show that the proposed system can factor most integers within 100 digits in less than 30 seconds on typical mobile devices, with a success rate above 95% and a GUI response time below 500 ms. The results demonstrate that porting integer factorization algorithms to WeChat Mini Programs is feasible and practically valuable for cryptographic education, algorithm verification and lightweight security tools.

**Keywords**: integer factorization; Pollard’s Rho; Miller‑Rabin; WeChat Mini Program; BigInt

第二章 相关理论与技术基础

### 2.1 大整数分解问题概述

大整数分解问题是数论与密码学中的经典难题：给定一个大整数 \(N\)，将其表示为素数的乘积，即 \(N=p_1^{e_1}p_2^{e_2}\cdots p_k^{e_k}\)。对一般的大整数，目前尚无已知的多项式时间算法，其计算复杂性被认为足够高，可以支撑公钥密码体制的安全性。

从算法角度看，整数分解方法大致可分为如下几类：

- 朴素方法：如试除法，其时间复杂度约为 \(O(\sqrt{N})\)，仅适用于小规模整数。
- 随机化方法：如 Pollard’s Rho 算法，利用随机迭代与概率分析实现期望意义下的性能提升。
- 筛法类算法：如二次筛法（QS）和数域筛法（NFS），在分解非常大的整数时性能突出，但实现复杂度较高。
- 并行与加速方法：如基于 GPU、FPGA 等平台的并行实现，通过硬件加速提升分解速度。

本文主要关注适合在移动终端实现的随机化算法和素性检测方法。

### 2.2 Pollard’s Rho 算法原理

Pollard’s Rho 算法是一种基于伪随机数序列与概率分析的整数分解算法。其核心思想是构造一个在模 \(n\) 意义下的伪随机序列：

\[
x_{i+1} = f(x_i) \mod n
\]

常用的迭代函数为 \(f(x) = x^2 + c \mod n\)，其中常数 \(c\) 通常取非 0、1 的小整数。算法利用 Floyd 或 Brent 判环算法，试图发现序列中的循环结构，从而通过计算 \(\gcd(|x_i - x_j|, n)\) 寻找非平凡因子。

在平均意义上，Pollard’s Rho 算法的时间复杂度约为 \(O(N^{1/4})\)，明显优于朴素试除法，同时空间复杂度较低，仅需保存少量中间变量，非常适合内存受限环境。

本文在具体实现中，对经典 Pollard’s Rho 算法做了以下适配与优化：

- 采用自适应的最大迭代次数，根据待分解整数位数动态调整参数；
- 引入类似 Brent 判环的策略，减少不必要的 \(\gcd\) 计算；
- 在主线程版本中将迭代过程按块拆分，通过异步调度避免长时间阻塞界面线程；
- 对找到的因子进行递归分解，配合 Miller‑Rabin 检测保证最终因子尽可能为素数。

### 2.3 Miller‑Rabin 素性检测

Miller‑Rabin 算法是一种常用的概率型素性检测方法。其基本思想是基于费马小定理与二次探测，将“\(n\) 为奇数且 \(n>3\)”的情况转化为对若干基 \(a\) 的幂模测试，从而判断 \(n\) 为“很可能是素数”或“必为合数”。

具体而言，将 \(n-1\) 写成 \(2^r d\) 的形式（\(d\) 为奇数），随机选择若干个 \(a\in[2,n-2]\)，计算：

\[
x = a^d \mod n
\]

若 \(x=1\) 或 \(x=n-1\)，则该轮测试通过；否则反复平方 \(x\) 并模 \(n\)，若在某一步出现 \(x=n-1\)，也视为通过；否则判定 \(n\) 为合数。重复多轮测试仍未发现反例，则可以以很高概率认为 \(n\) 为素数。

在实现中，本系统使用 Miller‑Rabin 算法作为：

- 分解前对输入整数进行素性初判，避免对明显为素数的整数做无效分解；
- 对分解得到的因子进行素性验证，标注因子是否为素数，提高结果可解释性。

### 2.4 微信小程序技术基础

微信小程序是运行在微信客户端中的轻量级应用，具有以下技术特性：

- 跨平台性：在 Android、iOS 和部分桌面平台上统一运行。
- 双线程架构：分为视图层（渲染线程）与逻辑层（JavaScriptCore 线程），通过数据绑定和事件机制进行通信。
- 本地存储与网络能力：支持本地存储接口，以及 HTTPS 网络请求，便于实现本地缓存和云端协同。
- Worker 线程：支持创建 Worker，在独立线程中执行耗时 JavaScript 代码，降低主线程压力。

在大整数分解场景下，这些特性带来的主要挑战包括：

- 逻辑层执行环境与原生 JS 略有差异，需考虑 BigInt 支持情况；
- Worker 能力受平台和版本限制，需处理不支持 Worker 的回退方案；
- 小程序对 CPU 占用、内存使用有一定限制，需对算法进行轻量化改造。

本文所实现的系统综合利用了微信小程序的数据绑定、页面路由、Worker 线程和本地存储能力，在用户体验与算法性能之间寻求平衡。

第三章 系统需求分析与总体设计

### 3.1 功能需求分析

结合任务书与开题报告，本系统的主要功能需求包括：

- 用户管理与登录注册  
  - 支持用户注册、登录与退出；  
  - 根据用户等级（普通、VIP、SVIP、管理员）控制可分解的最大位数与云端能力；  
  - 管理员拥有用户管理与数据导出等高级权限。

- 大整数输入与校验  
  - 支持用户在分解页面输入任意长度的十进制大整数；  
  - 对输入内容进行格式校验（仅允许数字），并给出位数统计和错误提示；  
  - 对 0 和 1 等特殊数字进行快速处理。

- 分解算法与模式控制  
  - 使用 Pollard’s Rho 与 Miller‑Rabin 对 100 位以内整数进行本地分解；  
  - 提供标准模式与快速模式两种分解模式；  
  - 对超出用户等级位数上限的输入给出提示并禁止启动分解。

- 进度展示与结果可视化  
  - 在分解过程中以文本与进度条形式展示实时状态、迭代次数和预计耗时；  
  - 分解完成后展示原数、因子列表、分解式、耗时、数字类型与分解程度；  
  - 支持一键复制分解结果，便于记录与分享。

- 历史记录管理  
  - 自动保存分解历史，包括原数、因子、分解式、时间和耗时等信息；  
  - 支持历史列表展示、成功次数统计、详情查看与一键清空。

- 个人中心与辅助功能  
  - 显示当前用户信息、等级、可分解位数和是否允许云端分解；  
  - 支持修改头像、查看帮助与关于信息；  
  - 管理员可导出用户数据与历史数据，方便线下分析。

### 3.2 性能与安全需求

- 性能需求  
  - 100 位以内整数，本地分解成功率 ≥ 95%，多数样例耗时 ≤ 30 秒；  
  - 界面响应时间 ≤ 500 ms，不能出现明显卡顿；  
  - 对超大整数或长时间未完成的计算，提供超时终止与部分分解结果。

- 安全需求  
  - 用户密码等敏感信息不以明文形式在前端长期存储；  
  - 历史记录和用户数据存储遵守微信小程序数据安全规范；  
  - 预留云端接口时，采用 HTTPS 通信并考虑必要的访问控制。

### 3.3 系统总体架构设计

系统采用四层总体架构：

- 表示层（前端页面）：包括首页、登录/注册、分解、历史、我的和管理员页面等，负责人机交互、输入输出与结果展示。  
- 业务逻辑层：定义分解流程控制、用户权限判断、模式切换和进度状态维护。  
- 算法核心层：实现 Pollard’s Rho 分解和 Miller‑Rabin 素性检测，在 Worker 或主线程中运行。  
- 数据与云服务层：包括本地存储（历史记录、当前用户）、数据导出工具和未来可扩展的云函数接口。

各层之间通过清晰的接口进行交互，前后端逻辑尽量解耦，便于后期维护与扩展。

- 注册时输入用户名、密码和希望的等级（普通/VIP/SVIP），系统在前期阶段可采用本地 JSON 模拟数据库；  
- 登录后，通过全局对象保存当前用户信息，并在各页面加载时校验登录状态，未登录则跳转至登录页面；  
- 管理员账号在初始化数据中预设，用于后续管理与测试。

#### 4.1.3 分解页面设计

分解页面是系统的核心交互界面，主要包含以下元素：

- 输入区域：单行或多行输入框，限制输入为数字字符，实时显示输入位数；  
- 信息提示区：展示输入合法性、数字类型（0、1、素数、合数、未知）与当前用户可分解的最大位数信息；  
- 分解模式选择：提供“标准模式”和“快速模式”单选按钮，用户可根据需求选择偏向完全分解或快速给出部分结果；  
- 进度与状态展示：使用进度条和状态文本描述当前迭代情况、已用时间与预设超时时间；  
- 结果展示区：显示原数、因子列表（附是否素数标识）、分解式和耗时等信息；  
- 操作按钮：包括“开始分解”“停止计算”“复制结果”等。

### 4.2 算法核心模块设计与实现

#### 4.2.1 BigInt 与高精度运算

考虑到 JavaScript 本身对整数范围的限制，系统统一采用 BigInt 表示大整数。用户输入以字符串形式传入，经合法性校验后再转换为 BigInt。为避免精度损失，所有分解算法均在 BigInt 范围内运算。

#### 4.2.2 Worker 线程与主线程协同

在支持的环境下，系统优先使用 Worker 线程执行分解计算：

- 主线程创建 Worker 并传递待分解整数的字符串；  
- Worker 内部实现 Miller‑Rabin、Pollard’s Rho 和递归分解逻辑；  
- Worker 在迭代过程中周期性通过消息机制向主线程报告进度；  
- 计算完成后，Worker 返回因子列表，主线程进行验证、整理与展示。

对于不支持 Worker 的环境，系统自动回退到主线程异步分块计算模式。通过将若干轮迭代封装为一个“块”，在每个块结束后使用异步调度让出执行权，从而保持界面刷新。

#### 4.2.3 Pollard’s Rho 与 Miller‑Rabin 结合策略

在具体实现时，系统采用以下策略：

- 对输入整数进行一次 Miller‑Rabin 检测，若判断为素数，则直接作为结果返回；  
- 对非素数情况，先使用小素数试除法快速去除易分解部分；  
- 余数部分由 Pollard’s Rho 算法处理，找到非平凡因子后递归分解；  
- 对每个候选因子再次进行 Miller‑Rabin 检测，尽量保证因子为素数；  
- 在时间超限或迭代次数达到上限时，返回当前已找到的因子作为部分分解结果。

### 4.3 数据存储与用户管理

#### 4.3.1 本地存储设计

系统采用微信小程序本地存储接口保存：

- 当前登录用户信息（用户名、等级、可分解最大位数等）；  
- 分解历史列表（原数、因子数组、分解式、时间、耗时、数字类型、分解程度）。

为控制存储空间占用，对历史记录数量和单条记录长度做了适当限制，例如只保留前若干个因子或截断过长的分解式。

#### 4.3.2 用户等级与权限控制

根据任务书要求，系统设定了以下等级与对应限制：

- 普通用户：0–20 位；  
- VIP 用户：21–50 位；  
- SVIP 用户：51–100 位；  
- 管理员：可分解更高位数的整数，并允许访问管理与导出功能。

在分解页面中，根据当前用户等级动态设置最大可输入位数，并在输入超过限制时给出错误提示并阻止计算。

性能测试表明，本文设计的轻量化 Pollard’s Rho 方案在移动终端上具有较好的实用性。

- Worker 创建失败或异常退出时，是否能回退到主线程计算方案。

测试结果显示，系统对典型异常场景均给出了合理处理和用户提示，程序稳定性较好。

第六章 总结与展望

### 6.1 工作总结

本文围绕“基于微信小程序的大整数分解系统设计与实现”这一课题，完成了从理论分析、系统设计到具体实现与测试的完整过程。主要工作包括：

- 综述大整数分解算法及相关研究现状，重点分析 Pollard’s Rho 与 Miller‑Rabin 算法的原理与复杂度；  
- 结合微信小程序技术特性，设计了“前端交互–算法核心–数据存储–云端协同”的总体架构；  
- 利用 JavaScript BigInt、Worker 线程和异步分块计算等技术，在移动终端有限算力环境下实现了大整数分解的轻量化适配；  
- 通过用户等级控制、历史记录管理和友好交互界面，构建了一个可用于教学和实验的微信小程序系统；  
- 通过功能与性能测试验证了系统在 100 位以内整数分解场景下的可用性与稳定性。

### 6.2 存在不足

尽管系统达到了预期的基本目标，但仍存在一些不足：

- 对极端难分解实例的性能仍然有限，在极个别情况下只能返回部分分解结果；  
- 云端协同分解功能目前仍处于预留阶段，尚未完全工程化部署和测试；  
- 本地数据加密与隐私保护机制还可以进一步强化。

### 6.3 后续研究方向

未来可以从以下几个方面继续改进与拓展：

- 引入更高效的分解算法（如改进版二次筛法）或多算法组合策略，提高大整数分解能力；  
- 完善云端协同架构，将超大整数任务交由高性能服务器或 GPU 集群处理；  
- 加强数据安全措施，对历史记录与用户数据进行加密存储和访问控制；  
- 优化前端可视化效果，将分解过程以因子树或图形方式展示，提高教学与演示效果。
